# Prestige Motors – Automotive Dealership Platform

Public dealership website + CRM + CMS + admin dashboard.
**Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS · Prisma · PostgreSQL**

## Features

| Area | What you get |
|---|---|
| Public site | Homepage (modular sections), inventory with 15+ filters, sorting & load-more, vehicle pages (gallery, specs, WhatsApp, test drive, inquiry, similar cars), About/Services/Financing/Privacy/Terms (CMS pages), Contact + map, Sell Your Car, Book Test Drive, FAQs, Reviews, Blog |
| Admin `/admin` | Dashboard, vehicle CRUD (duplicate, publish, feature, sold/reserved, photo reorder), brands, categories, features, CRM (status, notes, assignment, CSV export), test drives, homepage section builder, pages, blog, testimonials, FAQs, navigation, media library, settings, users & roles, activity log |
| Security | bcrypt, signed httpOnly session cookies, RBAC enforced server-side, Origin-based CSRF check, zod validation, HTML sanitisation, magic-byte upload validation, rate limiting, honeypots, audit log |
| SEO | Dynamic metadata, canonical URLs, Open Graph, `sitemap.xml`, `robots.txt`, Schema.org `Car`/`Offer`, `AutoDealer`, `BreadcrumbList`, `FAQPage`, `BlogPosting` |
| Pakistan defaults | PKR / “Rs.”, lacs/crore display, +92 phone normalisation, Asia/Karachi, 8 default cities, auction grade / import year / verified mileage / token tax / customs fields |

## Quick start (Windows, macOS, Linux)

Requires **Node.js 20+** and **PostgreSQL 14+**.

```bash
npm install
cp .env.example .env        # then edit values (see below)
npx prisma migrate deploy   # create tables
npm run db:seed             # sample data + Super Admin
npm run dev                 # http://localhost:3000   (admin: /admin)
```

No PostgreSQL installed? For **local development only** this repo includes a
no-installer database: run `npm run db:local` in a separate terminal (creates database `dealership`,
user/password `postgres`/`postgres` on port **5433** — use that in `DATABASE_URL`; change with `DEV_DB_PORT`). The site runs on **http://localhost:3010** (`npm run dev` / `npm run start`), chosen so it does not clash with other projects on 3000/5432. On Windows you can simply double-click `Start Website.bat`.

### Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `AUTH_SECRET` | 32+ random chars; signs sessions. `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `NEXT_PUBLIC_SITE_URL` | Public URL (canonical links, sitemap, WhatsApp message links). Use `https://…` in production — this also turns on `Secure` cookies |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | Super Admin created by the seed (password ≥ 10 chars) |
| `CLOUDINARY_*` | Optional. If all three are set, images upload to Cloudinary; otherwise they are stored in `./uploads` on the server's disk |

### Admin account setup
1. Set `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD` in `.env`, run `npm run db:seed`.
2. Sign in at `/admin/login`, open **Users & roles**, create staff accounts, then change the seed password (edit the user).
3. The seed is idempotent: it never overwrites existing data (sample vehicles/sections are only added to an empty database).

## Honest notes / known limits
- **Roles & permissions** are modelled as an enum + code matrix (not DB tables). This is simpler and safer for five fixed roles; moving to DB tables is possible if you need custom roles.
- **Rate limiting** is in-memory (per process). Fine for one server; use Redis if you run several instances.
- **Local image storage** needs a persistent disk (VPS/Docker volume). On serverless hosts (Vercel) configure Cloudinary.
- **Sample images are vector placeholders** generated by the seed — replace them with real photographs from the admin.
- Google Maps uses a plain embed URL (no API key needed). WhatsApp uses `wa.me` links (no API key needed).
- Rich content (pages/blog) is edited as sanitised HTML in a textarea, not a WYSIWYG editor.
- The admin UI is not covered by browser automation tests; unit tests cover core logic and the API was smoke-tested end-to-end (see docs/DEPLOYMENT.md).

- **Lead email alerts:** set SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS (and optionally SMTP_FROM, NOTIFY_EMAIL) in .env. Alerts go to NOTIFY_EMAIL or the Settings email. Without SMTP, leads are still saved to the CRM and nothing is sent.
